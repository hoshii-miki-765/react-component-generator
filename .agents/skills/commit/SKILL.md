# Commit

현재 작업 트리의 변경사항을 사용자가 이해하기 쉬운 커밋으로 정리한다. 사용자가 이 스킬의 트리거에 해당하는 커밋 요청을 하면, 해당 요청을 커밋 실행 승인으로 간주한다.

## 절차

1. `git status --short`와 `git diff`를 읽어 변경 파일, 의도, 테스트 영향과 기존 사용자 변경을 파악한다. 필요하면 `git diff --staged`도 함께 확인한다.
2. 변경사항을 독립적으로 되돌리거나 검토할 수 있는 논리적 단위로 분류한다. 관련 없는 사용자 변경은 포함하지 않는다.
3. 각 단위에 대해 한국어 Conventional Commit 메시지를 제안한다. 형식은 `feat: 요약`, `fix: 요약`, `refactor: 요약`, `chore: 요약` 중 목적에 맞는 타입을 사용한다. 요약은 짧고 변경 결과를 설명한다.
4. 각 단위의 파일을 스테이징하고 커밋한다. 별도 승인 단계는 두지 않는다. 사용자가 일부 범위만 지정하면 그 범위만 반영한다.
5. 커밋 후 `git status --short`로 결과를 확인하고 커밋 해시, 메시지, 남은 변경사항을 보고한다.

## 경계

- 이미 스테이징된 변경은 사용자의 의도를 확인하기 전 재설정하거나 수정하지 않는다.
- 빈 커밋은 만들지 않는다.
- 푸시, 브랜치 생성, amend, rebase는 이 스킬의 범위가 아니다. 사용자가 별도로 요청한 경우에만 수행한다.
